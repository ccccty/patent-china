# 排版规范（唯一真源）

本文件由用户提供的《一种基于多尺度非对称融合网络的水稻分布智能制图方法 250630(1).docx》逐段/逐样式逆向得到，是 `tools/emit_patent_docx.py` 的硬编码依据。改本文件必须同步改脚本。

## 一、文档形态

单份 `.docx`，`w:sectPr` 分 **5 节**，每节独立页眉与页码，每节另起一页：

| 节 | 页眉文字 | 内容 |
|----|----------|------|
| 1 | 说明书摘要 | 摘要正文（一段，≤300 字） |
| 2 | 摘要附图 | 一张图，无图题 |
| 3 | 权利要求书 | 权项 1…n，手打序号 |
| 4 | 说明书 | 发明名称（居中加粗）+ 技术领域 / 背景技术 / 发明内容 / 附图说明 / 具体实施方式 |
| 5 | 说明书附图 | 图1…图N，图题在图**下方**居中 |

## 三、段落样式

### Normal（文档默认）

```xml
<w:pPr><w:widowControl w:val="0"/><w:spacing w:line="360" w:lineRule="auto"/><w:jc w:val="both"/></w:pPr>
<w:rPr><w:rFonts w:ascii="Calibri" w:hAnsi="Calibri" w:eastAsia="宋体" w:cs="Times New Roman"/><w:kern w:val="2"/><w:sz w:val="21"/></w:rPr>
```

行距 360 = 1.5 倍；两端对齐。**注意 `widowControl=0`**，否则末页会出现孤行。

### 正文段

| 属性 | 值 |
|------|-----|
| 字体 | 宋体（`ascii`/`hAnsi`/`cs` 全为宋体，不留给 Calibri 回退） |
| 字号 | 四号 = `w:sz w:val="28"`（14 pt） |
| 首行缩进 | `w:firstLine="560" w:firstLineChars="200"`（2 字符） |
| 对齐 | 继承 Normal 的两端对齐 |
| 行距 | 继承 1.5 倍 |
| 段前段后 | 0（不设 spacing before/after） |

正文段落须把 rPr 写进**段落标记的 `w:pPr/w:rPr`**（与样板一致），并同时设到每个 run。

### 说明书标题（第 4 节首行）

| 属性 | 值 |
|------|-----|
| 字体 | 宋体 |
| 字号 | 三号 = `w:sz w:val="32"`（16 pt） |
| 加粗 | 是（`w:b` + `w:bCs`） |
| 对齐 | 居中 |
| 首行缩进 | 无 |

> 样板此处 `w:sz=28`，但实际 run 为 16 pt（run 级覆盖）。以 **16 pt 加粗居中** 为准。

### 章标题（技术领域 / 背景技术 / 发明内容 / 附图说明 / 具体实施方式）

| 属性 | 值 |
|------|-----|
| 字体 | 宋体 |
| 字号 | 四号 14 pt |
| 加粗 | 是 |
| 对齐 | 左（发明内容一节显式 `w:jc w:val="left"`） |
| 首行缩进 | 无 |
| 段前段后 | 0 |

### 图题 / 表题

| 属性 | 值 |
|------|-----|
| 字体 | 宋体 |
| 字号 | 四号 14 pt |
| 加粗 | 否 |
| 对齐 | 居中 |
| 首行缩进 | `w:firstLine="560" w:firstLineChars="200"`（样板如此，居中后视觉上仍居中） |

**图题在图下方**（第 5 节），**表题在表上方**。

> 样板图5、图6 的图题段落里残留楷体空 run（WPS 编辑痕迹），非规范。脚本统一用宋体，不复制该瑕疵。

### 公式段

| 属性 | 值 |
|------|-----|
| 布局 | 独立成段，段内仅 OMML |
| 对齐 | 居中 |
| 首行缩进 | 无 |
| 编号 | 本技能按用户选定：**保留 (1)(2) 编号**，右对齐于行末（样板无编号，此项为有意偏离） |
| **run 字体** | **每个 `m:r` 必须显式带 `<w:rPr>`：`w:rFonts` 的 ascii/hAnsi/cs 全为 `Cambria Math`，`w:sz` 与 `w:szCs` 均为 `28`**。漏了这些，公式会比正文小一圈，中文字体还会串进公式。`m:ctrlPr` 里也要补 |
| 段落标记 | 公式段的 `pPr/rPr` 也要写同样字体，否则段末空 run 会掉回 10.5 pt |

> 实测样板 294 个 `m:r` 全部显式声明 `Cambria Math + sz=28`，无一例外。这是「公式看着发飘、比正文小」的真正原因，不是 `Normal` 样式没继承。

编号实现：公式段用右对齐制表位（`w:tabs`，右制表位在右边界），公式居中 + 编号贴右。若实现困难，退化为「公式居中，编号紧随其后」，不得丢编号。

#### 长公式必须拆行（渲染级硬约束）

OMML 公式在 Word/LibreOffice 里是**不可断对象**，宽度超过版心时不会换行，而是整行压出右边界。

实测：四号字下，一条「`A = …,\quad B = …,\quad C = …`」式的复合公式（源码约 160 字符）会把内容推出右边距 **1.71 cm**，且 XML 完全合法——所有 XML 级 checker 都查不出来。

规则：

- 公式源码超过 **105 字符**且含 `\quad` / `\qquad` 时，按分隔符拆成多行，**同一编号只出现一次**（编号在最后一行行末）。
- 拆行用 `w:br` 换行，不要拆成多个独立公式段（会变成多个编号）。
- 拆行后整段落改为左对齐（多行公式居中会左右参差），多行各自成一式。
- 兜底：仍超宽的单条公式按长度降字号（≤130 字符四号、≤170 字符 13 pt、更长为 12 pt），但降字号只能救回很小一点，不能替代拆行。

### 套话段

样板固定套话（原样输出，不改写）：

- 附图说明引导段：「为了更清楚地说明本发明实施例的技术方案，下面将对实施例描述所需要使用的附图作简单地介绍，显而易见地，下面描述中的附图仅仅是本发明的一些实施例，对于本领域普通技术人员来讲，在不付出创造性劳动的前提下，还可以根据这些附图获得其他的附图。」

- 有益效果收尾：「当然，实施本发明的任一产品并不一定需要同时达到以上描述的所有优点。」
- 实施例递进说明：「本说明书中的各个实施例均采用递进的方式描述，各个实施例之间相同相似的部分互相参见即可，每个实施例重点说明的都是与其他实施例的不同之处。尤其，对于装置、设备、非易失性计算机存储介质实施例而言，由于其基本相似于方法实施例，所以描述的比较简单，相关之处参见方法实施例的部分说明即可。」
- 保护范围收尾：「以上内容仅仅是对本发明的构思所作的举例和说明，所属本技术领域的技术人员对所描述的具体实施例做各种各样的修改或补充或采用类似的方式替代，只要不偏离发明的构思或者超越本申请所定义的范围，均应属于本发明的保护范围。」

## 四、页眉与页脚

### 页眉

| 属性 | 值 |
|------|-----|
| 字体 | 黑体（`ascii` 与 `eastAsia` 均为黑体） |
| 字号 | 四号 14 pt |
| 加粗 | 是 |
| 对齐 | 左 |
| 下边框 | `w:pBdr/w:bottom w:val="single" w:sz="6" w:space="0"` |
| 行距 | `w:line="240" w:lineRule="auto"`（单倍） |

页眉文字按第一节表所列，逐节不同。**每节必须切断与前一节的链接**（`header.is_linked_to_previous = False`），否则五节会共用第一个页眉。

### 页脚

居中 `PAGE` 域：

```xml
<w:pPr><w:jc w:val="center"/></w:pPr>
<w:r><w:fldChar w:fldCharType="begin"/></w:r>
<w:r><w:instrText xml:space="preserve"> PAGE \* MERGEFORMAT </w:instrText></w:r>
<w:r><w:fldChar w:fldCharType="separate"/></w:r>
<w:r><w:t>1</w:t></w:r>
<w:r><w:fldChar w:fldCharType="end"/></w:r>
```

页码**每节重编为 1**（实测样板第 2–5 节的 `sectPr` 均带 `w:pgNumType w:start="1"`；第 1 节无该元素）。脚本按此实现，`--continuous-page` 可改为全文连续。

## 五、表格

| 属性 | 值 |
|------|-----|
| 边框（**双层结构**） | 表级 `tblBorders` 六向全 `w:val="none" w:sz="0"`；**同时每个 `tc` 的 `tcBorders` 四向写 `w:val="single" w:color="000000" w:sz="4"`**。视觉上是有框线的表格 |
| 布局 | `w:tblLayout w:type="fixed"`；模板 `tblW w:w="8696"`（超版心 8312，是样板瑕疵）。脚本按 **8272**（版心 − 40 dxa）出稿：正好等于版心时，边框描边与网格舍入会把表压出右边界 |
| 单元格边距 | 左/右 108 dxa，上/下 0 |
| 垂直对齐 | `w:vAlign w:val="center"` |
| 表头 | 加粗（`w:b` + `w:bCs`）；模板仅给首行首二列加粗（7/9 未加粗），正式稿**首行整行加粗** |
| 单元格字体 | 宋体，小四 `w:sz=24`（12 pt） |
| 颜色/斜体 | `w:color=000000`、`w:i w:val="0"`（显式关闭） |
| 表题 | 居中在表**上方**，宋体四号不加粗 |
| 位置 | 说明书正文内，**不**当附图 |

> **最易踩的坑**：只写表级 `tblBorders=none` 会得到一张完全没线的表。模板视觉上的线全部来自单元格级 `tcBorders`。脚本默认两层都写（表级 none + 单元格 single），`--no-table-borders` 才出无框线表。

## 六、图片

| 项 | 规则 |
|----|------|
| 嵌入方式 | `python-docx` `add_picture`，段落居中 |
| 最大宽度 | **14.5 cm**（版心 14.66 cm 留 0.16 cm 余量） |
| 最大高度 | 20 cm（留出图题与页眉） |
| 缩放 | 等比，取宽高约束的较小缩放比 |
| 图号 | **不画进图内**，只写在图题段 |
| 第 5 节 | 每图后紧跟居中图题「图N」 |
| **环绕距离** | **`wp:inline` 的 `distT/distB/distL/distR` 必须显式写 `0`** |

> **必踩的坑**：`wp:inline` 不写 `distL/distR` 时，渲染器会套用 0.32 cm 的默认环绕距离，把图整体右移约 18 px（144 dpi），右侧压出版心。宽度取满 14.66 cm 时必然越界；显式写 0 且宽度退到 14.5 cm 才真正贴版心。

## 七、与旧交底书形态的关键差异

| 项 | 旧（交底书） | 新（申请文件） |
|----|--------------|----------------|
| 文档 | 单节 | 5 节 |
| 页眉 | 无 | 5 个不同页眉 + 下边框 |
| 页码 | 无 | 页脚居中 PAGE 域 |
| 纸张 | Letter（默认） | A4 |
| 正文 | 宋体 10.5 pt | 宋体 14 pt |
| 缩进 | 无 | 首行缩进 2 字符 |
| 章标题 | Heading 1/2（蓝色 14pt/13pt） | 宋体 14pt 加粗（无 Heading 样式） |
| 图表位置 | 图内嵌正文 | 图集中第 5 节，表在正文 |
| 结构 | 一～六章 + 1.1/3.4.1 | 技术领域/背景技术/发明内容/附图说明/具体实施方式 |
| 查新 | 正文 1.1 含公开号与 URL | **不入正文**，另出附件 |
