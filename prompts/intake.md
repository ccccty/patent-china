# S0 · 收材料与开案

## 先定三件事

| 项 | 从哪来 | 缺了怎么办 |
|----|--------|-----------|
| 发明名称 | 材料标题 / 用户口述 | 按「一种 + 技术手段 + 对象 + 方法」自己拟，进核实清单 |
| 技术领域 | 材料第一章 / 论文引言 | 从手段判断，写一句 |
| 要保护什么 | 材料的创新段 / 用户强调点 | **必须问**，这是唯一不能猜的 |

其余（申请人、发明人、地址、代理机构）**不要问**，一律留空进核实清单。问多了打断流程，且这些和交底内容无关。

## 开案目录

```
outputs/patent-china/{案件标识}_{YYYYMMDDHHmmss}/
├── assets/                 附图
├── 材料清单.md              S1 产物
├── claim_tree.yaml          S4 产物
├── 权利要求书.md            S5
├── 说明书.md                S7
├── 摘要.md                  S8
├── {案件名}_{ts}.md         S9 合并稿
├── {案件名}_{ts}.docx       S10 主交付
├── 查新与区别定位_{ts}.md   S3 旁路
└── 核实清单_{ts}.md         S11 旁路
```

案件标识取发明名称去掉「一种」后的主干，截 20 字以内，不留空格与标点。

## 时间戳

`YYYYMMDDHHmmss` 取**当前机器时间**，实时取，不要硬编码。同一秒内重复生成会撞名，加 `_1` 后缀。

## 材料清点

用户给的东西先列一遍，不要漏：

- 论文：正文、图、公式、实验表、代码仓库、LaTeX 源
- 交底书：已有章节可直接映射到五部分
- 口头方案：技术问题 → 手段 → 效果，三句话
- 数据：精度表、消融表、对比表
- 图：框架图、模块图、流程图、结果图

**图片一律先登记路径与内容，S6 再决定用哪张。** 不要在这一步就判死刑。

## 开工前一句话

向用户复述：要保护的对象、核心技术手段、打算写几条权项、图大概几张。让用户在写之前就能拦住方向错误。

这段复述不要写进任何产出文件。

## 禁止

- 材料没看完就开始写权利要求
- 因为缺申请人/发明人就停下
- 因为图不齐就停下（先写正文，图后补）
- 把「我先确认几个问题」拖成多轮来回；一次问完，然后一直写到成稿
