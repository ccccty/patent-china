# 权利要求书 · 权项策略

先写一句话：`问题 → 手段 → 效果`。只用材料里已有的技术特征；材料没有的不进独权，缺口记入问题清单。

## 一、分层与层次枚举

| layer | 落点 | 判断标准 |
|-------|------|----------|
| 必要技术特征（不写 layer） | 独立权项 | 删去后无法解决所述技术问题，或无法与最接近方案区分 |
| `preferred_param` | 从属 | 对独权某要素给出阈值、权重、窗口长度、比例或取值范围 |
| `branch` | 从属 | 写独权未覆盖的例外、判定分支、回环或失败路径 |
| `system_map` | 从属 | 把方法步骤落到执行模块，供系统独权与从属呼应 |
| `embodiment` | 从属 | 只写架构、结构、超参等实施细节，不改变保护范围 |

独权只卡必要技术特征；阈值、权重、数据格式、模块名称、分支例外一律下沉从属。

## 二、落盘结构

`point` 即该条要点一句话；`refs` 只能写在先权项。

```yaml
claims:
  independent:
    - {id: 1, kind: method, name: 一种……方法, core: 手段一句话}
    - {id: 2, kind: system, name: 一种……系统, modules: [数据获取模块, 样本构建模块, 特征提取模块, 制图输出模块]}
  dependents:
    - {id: 3, refs: [1], layer: preferred_param, point: 所述……包括……与……}
    - {id: 4, refs: [3], layer: branch, point: ……不成立时改判为……}
    - {id: 5, refs: [1], layer: system_map, point: ……模块用于执行S2}
    - {id: 6, refs: [5], layer: embodiment, point: ……的卷积核与步长}
```

## 三、硬约束

- 方法独权恒为 1；系统独权紧随编号 2；从属自 3 起连续编号，不跳号、不重号。
- 系统独权的模块与方法步骤一一对应，不新增无方法支撑的模块。
- 从属单引在先权项；从属 5～10 条，同一从属链不超过三级。
- 材料缺的数值不补，权项内不出现待定表述；确需说明的写进问题清单。
