# S1 · 材料扫描

把用户给的所有东西扫一遍，登记成册，后面写稿只从这里取材，不凭记忆。

## 产出：`材料清单.md`

```markdown
# 材料清单

## 论文/文档
| 路径 | 类型 | 可提取什么 |

## 公式
| 编号 | 出处 | LaTeX | 用途 | 是否进正文 |

## 表格与数据
| 编号 | 出处 | 规模 | 是否进说明书 |

## 图片
| 文件 | 内容 | 候选用途 | 是否可用作附图 |

## 代码/仓库
| 路径 | 关键文件 | 能确认什么 |
```

## 扫描要点

### 论文正文

- 技术问题在第几节、用什么句式提的 → 决定背景技术的落点
- 方法与步骤 → 权项的 S1…Sn 骨架
- 实验与对比 → 具体实施方式的表
- **不要**把论文的「相关工作」整段搬进背景技术，只取与本案最接近的那一类做法

### 公式

每条登记 LaTeX 与用途。判据：

| 情况 | 处理 |
|------|------|
| 是方法的计算核心 | 进说明书，带编号 `(n)` |
| 只是评价指标（PSNR、IoU 定义） | 一般不写，除非权项要卡它 |
| 材料里是图片不是公式 | 手工转录成 LaTeX；转不了就写文字关系，**不要截图进 Word** |
| 出现 `\tilde` `\hat` `\bar` | 改写符号，OMML 对这些支持差 |

### 表格

材料里已有的多行同结构数据（精度对比、消融、参数配置）→ 说明书**必须保留表**，不能揉成一句「效果良好」。材料没有的不要造。

### 图片

逐张判：

| 图的内容 | 能否当附图 |
|----------|-----------|
| 总体框架/网络结构 | 能，但要重画成黑白线框 |
| 方法流程图 | 能，最优先 |
| 子模块内部结构 | 能 |
| 精度对比曲线/柱图 | 能，作为对比图 |
| 制图结果/效果图 | 能，作为结果图 |
| 截图、界面、照片、宣传图 | 不能 |
| 彩色热力图 | 一般不能，除非本身就是数据图 |

**论文里的彩色图不能直接用**，S6 要重画或转黑白。

### 代码

代码只用来确认实现细节（层数、超参、损失函数具体形式），**不要**把代码贴进说明书，也不要写成「如代码所示」。

## 自检

- [ ] 每个后续要用的公式都能在清单里找到出处
- [ ] 每张图都判过能不能用，不是留「待定」
- [ ] 表格的行列数记下了，写说明书时照着建
- [ ] 没有把材料里的未来工作、局限性写成本案的技术问题

## 不要做

- 不要扫描 `node_modules` `dist` `build` 这类目录找图
- 不要把材料里的文献综述当现有技术写进正文
- 不要因为图是彩色的就跳过登记
