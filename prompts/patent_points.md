# S2 · 抽专利点

把技术内容切成「哪些必须写进独权（必要技术特征）」和「哪些只配写从属（优选）」。这一步没做对，后面全塌。

## 产出形状

每条一个编号 `F1…Fk`，字段固定：

```yaml
- id: F1
  name: 多模态影像数据集构建
  is_essential: true          # 去掉它方案就不成立 → 进独权
  evidence: "论文 3.1 节 + 图3"
  supports: [S1]
  note: ""
```

## 必要性判定（删除测试）

逐个特征问：**把它删掉，本发明还能解决所述技术问题吗？**

- 不能 → 必要，进独权
- 还能 → 优选，进从属
- 拿不准 → 按「必要」处理，宁宽勿窄；从属数量不受限，独权写窄了很难救

## 常见误判

| 误判 | 后果 | 正确做法 |
|------|------|----------|
| 把超参（学习率、批大小、阈值取值）当必要特征 | 独权过窄，易规避 | 进从属，写「取值范围」 |
| 把具体网络层数、模块个数当必要特征 | 同上 | 进从属 |
| 把「用 GPU 训练」当技术特征 | 不是技术手段 | 删除 |
| 把效果当特征（「提升精度」） | 效果不能限定方案 | 挪到有益效果 |
| 漏掉数据预处理 | 独权缺步骤，说明书与权项对不上 | 与独权步骤表逐条核对 |

## 与权项的映射

| 专利点 | 去向 |
|--------|------|
| `is_essential: true` | 权利要求 1（方法独权）的 `S1…Sn` |
| `is_essential: true` 且是系统/模块 | 系统独权（权利要求最后一条）的模块表 |
| `is_essential: false` | 从属权项，按 `claim_strategy.md` 分层 |

**独权的步骤数 = 主流程图框数**。多了少了都要回头改，不能图文不一致。

## 不要做

- 不要在这一步写完整句子。只写名词短语 + 出处。
- 不要在这一步判断新颖性。那是 S3 的事，且结论也不进正文。
- 不要为了凑数把非必要特征标成必要。
