# 说明书附图（S6）

图是申请文件的硬要件。本技能的图分两类：**脚本画的**（流程图、框图）与**材料转的**（对比图、结果图）。全部图集中在第五节，正文只写「如图N所示」，图本身与图题都不进说明书正文。附图必须是黑白线框。**图号不画进图里**，只写在图题段。

## 图型与权项对应

| `kind` | 画什么 | 对应权项 | 优先级 |
|--------|--------|----------|--------|
| `flowchart` | 方法步骤图 | 方法独权 S1…Sn | 必画，图1 |
| `block_diagram` | 系统／装置总体结构框图 | 系统独权 | 有系统独权就必画 |
| `module_detail` | 子模块内部结构 | 从属权项 | 从属提到具体模块才画 |
| `comparison` | 精度／性能对比图 | 支撑有益效果 | 材料有数据才画 |
| `result_map` | 制图／检测结果图 | 支撑实施例 | 材料有结果才画 |

**独权步骤数 = 流程图框数**。不为凑图去画权项没写的东西，也不画权项没点到的剖视、爆炸、多状态。

## flowchart 方法步骤图

- 何时画：每案必画，排在全部图的最前，为图1。
- 画法：自上而下单列，框内写「步骤1：<步骤名>」，与权项 1 的 `S1、`…`Sn、` 同序同数、逐字同义；不画分支、不画回环、不画判断菱形——分支与回环写进从属权项和实施例。框内不写 `S1`、不写 `201`、不写「步骤一」。
- 命名：`assets/fig1.png`。
- 覆盖权项：权项 1 的全部步骤及先后关系，一框一步，框内文字可在权项原文里逐字找到。

## block_diagram 系统结构框图

- 何时画：有系统（装置）独权，或方案由多个可命名单元串成时画，通常为图2。
- 画法：左输入右输出，中间按数据流分列；`subgraph` 虚线框分组表示「数据准备／特征提取／融合／解码」各段，框内只写模块中文全称。不拉引出线、不标 `(10)(20)` 件号。各列按自身模块数自上而下紧排，不把模块少的列撑成与邻列相同槽位。
- 命名：`assets/fig2.png`。
- 覆盖权项：系统独权的全部单元，以及从属权项新增的单元；每个框都要能在权项或说明书里找到同名表述。

## module_detail 子模块内部结构

- 何时画：某条从属权项把一个模块拆成若干子步骤／子单元，纯文字说不清数据流时画；每个这样的模块一张，排在框架图之后。
- 画法：顶部写模块全称，纵向串子步骤，横向标出张量与数据形态的变化；公式只留在说明书正文，图上只写「最大池化」「上采样」「通道拼接」「注意力加权」这类操作名，不写公式。
- 命名：`assets/fig3.png` 起顺延。
- 覆盖权项：该模块对应的那条从属权项的全部子特征，一框一特征；子特征超过 6 个时按阶段合并，合并处必须是权项里已有的层级。

## comparison 精度对比图

- 何时画：说明书有定量对比表或对比实验时画；无实测数据不画，也不许估数据。
- 画法：柱状或折线，纵轴写指标名（mIoU、F1 等），横轴写方法名；本案方法与对比方法靠填充和线型区分——本案实心黑柱，对比白底黑框柱或虚／点线；图例放图内右上或图下，不压数据。
- 命名：`assets/figN.png`，N 接在前一图之后。
- 覆盖权项：有益效果里被量化的那几条效果，数值与说明书表格严格一致；表里没有的方法不上图。

## result_map 制图结果图

- 何时画：方案落到遥感／医学／检测等出图场景，且说明书描述了结果验证时画。
- 画法：只放本案方法的输出；多时相或多区域用 (a)(b)(c) 子图并在图内标子图号（子图号属图内容，不是图号）。图内标研究区、年份、比例尺与图例，全黑白灰阶，不同类别用斜线、点阵、实心等填充纹理区分。
- 命名：`assets/figN.png`，接在前一图之后。
- 覆盖权项：解码重建、结果输出、验证这几步对应的权项要素，体现「生成高分辨率结果」；不放训练过程图、不放网络结构图。

## 黑白线框

mermaid 出的彩色 PNG 不能直接当正式附图。`tools/render_figures.py` 已内置黑白主题与二值化，直接用：

```powershell
# 从含 mermaid 围栏的 .md 批量出图，直接出黑白紧裁 PNG
python tools/render_figures.py -i figures_src.md --out-dir assets --blackwhite

# 单块 .mmd
python tools/render_figures.py --block assets/flow1.mmd --out assets/fig1.png --blackwhite

# 材料图（彩色论文图）转黑白
python tools/render_figures.py --binarize assets/raw_framework.png --out assets/fig2.png
```

渲染器强制注入的 init 就是 `theme:base` + 全白填充 + 全黑线，出图后按内容包围盒紧裁，并做二值化（阈值 200）。实测输出灰度占比 0.00%，即纯黑白。

两条必须遵守的写作约束：

1. mermaid 块内**不用中文弯引号** `“ ”`，用 ASCII `"`，否则渲染失败。
2. 节点文字用 `["…"]` 包起来，含 `：`、`（）`、`/` 时要加引号，否则解析报错。

手工兜底（脚本不可用时）：mermaid 首行加 `%%{init: {'theme':'base','themeVariables':{'primaryColor':'#ffffff','primaryTextColor':'#000000','primaryBorderColor':'#000000','lineColor':'#000000'}}}%%` → 导出 SVG → 按内容包围盒裁切 → 转 300 dpi PNG → 核对背景纯白、线条纯黑、无渐变阴影。

材料转来的图：框架图重画成黑白框图；柱状／折线图可二值化；遥感影像类结果图保留灰度，不强行二值化（会丢信息）；截图与照片不用。不用 ASCII 字符画框图（`+---+` 这种），不把彩色 mermaid 图直接塞进 Word。

## 图题

- 第四节「附图说明」逐条写 `图1为……；`，每条一句独立成段，末条改用句号；只写图名与图型，不写图中内容和结论；正文每处「如图N所示」在此必须有对应条目。
- 第五节每张图**下方**居中单独一段，只写 `图1`、`图2`，**不带任何说明文字**。
- 图题宋体四号、不加粗、居中；一个图题段只对应一张图，图题不与图同段。
- 图题不手写：Markdown 里按 `![图1](assets/fig1.png)` 写，脚本按 `::: 说明书附图` 节内的出现顺序生成图题。

## 尺寸

- 单图最大宽 **14.66 cm**（21 − 3.17×2），最大高 **20 cm**，等比缩放，取两个约束中较小的缩放比。
- 图宽不得超正文净宽；超宽先重排横向布局，不靠缩字号硬塞。
- 出图时按目标尺寸反推画布，不要先出超大图再缩。

## 摘要附图

单独一节，只放一张，不配图题，不放任何文字，尺寸同上。选图规则见 `abstract_builder.md`：默认总框架图（`block_diagram` 那张，复用 `assets/fig2.png`，另存 `assets/abstract.png`），无框架图才退化为 `flowchart` 主流程图。
